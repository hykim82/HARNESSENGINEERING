### §1-3 이것이 인덱스 설계에 갖는 함의

분할 후 이 **19개 파일(경로 문자열 기준)**이 `docs/enforcement-known-gaps.md`라는 단일 경로를 참조하고 있으므로, 분할이 일어나면 이 참조들은 (a) 인덱스 파일을 거쳐 간접 참조하도록 바뀌거나, (b) 개별 shard 경로를 직접 알아야 한다. **인덱스가 존재하는 이유가 바로 이것** — 소비자가 "gap N이 어느 shard에 있는지"를 매번 grep으로 찾지 않고 인덱스 1회 조회로 얻게 하는 것.

## §2 스키마 초안

### §2-1 파일 형식·위치

- 경로(제안): `docs/enforcement-known-gaps/index.json`
- 형식: JSON(이 저장소의 다른 매니페스트, 예 `scripts/check/enforcement-inventory.json`과 일관된 손-유지 가능 형식).

### §2-2 필드

```jsonc
{
  "schemaVersion": 1,
  "generatedAt": "2026-08-11T00:00:00Z", // 마지막 갱신 시각(ISO-8601, authority clock 기준)
  "shardByteLimit": 204800, // §2-3(split-design 문서) 상한, 바이트
  "gaps": {
    "1": {
      "shard": "001-060.md",
      "classification": "KNOWN GAP",
      "ncTrack": "NC-1",
    },
    "10": {
      "shard": "001-060.md",
      "classification": "BLOCKED",
      "ncTrack": "NC-1",
      "note": "gap 아님 — 방어 성공 기록(§1-6 split-design 참조)",
    },
    "94": {
      "shard": null,
      "classification": "KNOWN GAP",
      "ncTrack": null,
      "note": "표 행 없음 — 산문 절만 존재(분할 시 등재 결정 필요, §3-3 split-design #1)",
    },
    // ...
  },
  "shards": {
    "001-060.md": {
      "startGap": 1,
      "endGap": 60,
      "byteSize": null,
      "path": "docs/enforcement-known-gaps/001-060.md",
    },
    // ...
  },
}
```

| 필드                              | 의미                                                                                                                                 | 누가 쓰는가                                             | 누가 읽는가                                                                                                     |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `schemaVersion`                   | 스키마 하위호환 판단용 정수                                                                                                          | HYK-232 분할 스크립트(최초 생성)                        | 정본 검사 스크립트(§3 split-design) — 알 수 없는 버전이면 `UNJUDGABLE`                                          |
| `generatedAt`                     | 인덱스 최종 갱신 시각                                                                                                                | 분할/append 스크립트(매 쓰기 시 갱신)                   | 사람(디버깅) — 검사 로직은 이 필드에 의존하지 않음(값 오차가 판정을 바꾸면 안 됨)                               |
| `shardByteLimit`                  | shard 마감 상한(바이트)                                                                                                              | 분할 스크립트(고정값, 설정 변경 시 갱신)                | 분할 스크립트(새 shard를 열지 판단) + 정본 검사(§3-3 상한 초과 RED 판정)                                        |
| `gaps.<N>.shard`                  | gap N이 있는 shard 파일명. `null`이면 "표 행 없음"(§3-3 결번 케이스)                                                                 | 분할 스크립트(최초) + 신규 gap append 스크립트(매 등재) | 정본 검사(핵심 조회 대상) + 사람(수동 조회)                                                                     |
| `gaps.<N>.classification`         | `KNOWN GAP`/`NEW DEFECT`/`BLOCKED`/`닫힘` 등 — §1-6(split-design)에서 실측한 "표 행이되 gap이 아닌 경우"를 기계가 구분하게 하는 필드 | 분할 스크립트(원본 표 행 파싱)                          | 정본 검사(§3-3 "실제 gap만" 카운트할 때 필터) + 인벤토리 재계수 스크립트(향후)                                  |
| `gaps.<N>.ncTrack`                | NC-1/NC-2/NC-3/`null`(해당 없음) — §2-1(split-design) 후보 A의 장점을 인덱스 필드로 흡수                                             | 분할 스크립트                                           | 검색·리포트 도구(향후, 이 라운드 범위 밖)                                                                       |
| `gaps.<N>.note`                   | 결번·특수 케이스 등 사람이 읽을 자유 텍스트                                                                                          | 분할 스크립트 또는 사람 수기                            | 사람만(검사 로직이 파싱하지 않음 — 자유 텍스트를 판정에 쓰면 §3-2 "애매하면 거부" 원칙 위반)                    |
| `shards.<file>.startGap`/`endGap` | shard가 담은 번호 구간(포함)                                                                                                         | 분할 스크립트                                           | 정본 검사(§3-3 인덱스-실물 드리프트 대조)                                                                       |
| `shards.<file>.byteSize`          | 마지막 측정 시점 shard 파일 크기                                                                                                     | append 스크립트(매 쓰기 후 갱신)                        | 정본 검사(상한 초과 판정 시 캐시 값 대신 **실시간 `stat`을 신뢰**하고 이 필드는 참고용으로만 — stale 위험 명시) |

### §2-3 이 라운드에서 미결정으로 남기는 것

- `gaps.<N>.shard = null`(결번, 예 #94)을 검사가 **RED로 볼지, 명시적 허용 예외로 볼지**는 HYK-232 실분할 시점에 "#94를 표 행으로 새로 등재할지"가 먼저 결정돼야 답이 나온다 — 이 라운드는 그 갈림길만 스키마에 필드(`note`)로 남겨두고 결정하지 않는다.
- shard 파일명 규칙(`{시작}-{끝}.md` vs 다른 명명)은 split-design §2-3의 제안이며 HYK-232에서 최종 확정.
