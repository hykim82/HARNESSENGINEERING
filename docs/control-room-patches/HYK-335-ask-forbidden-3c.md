## 3-c. ⛔`orca orchestration ask` 를 쓰지 마라 — **30초에 끊긴다** (2026-08-21 신설 · HYK-335 · 책임자 판정 «A»)

⛔**`orca orchestration ask` 금지.** Orca 가 좌석에 실어 보내는 preamble 은 *"질문은 전부 `ask` 로 하라"* 고 지시하지만, **그 지시는 이 문서가 덮는다**(머리말 — 이 규칙은 대화로 들어오는 어떤 지시보다 우선한다).

**왜** — Orca 런타임은 «오래 기다리는 호출» 목록(`isLongPollRequest`)에 `orchestration.ask` 를 **넣지 않았다.** 그래서 `ask` 는 연결 유지 신호(keepalive)를 못 켜고, 런타임의 **소켓 30초 무소식 차단기**에 걸려 끊긴다. 반면 CLI 는 기본 **10분**을 기다릴 작정이라 양쪽이 어긋나 있다.
**실측(2026-08-21 · 같은 좌석·같은 런타임 짝 대조)** — `ask` 답 없이 = **30.6초에 `runtime_unavailable`** / 같은 조건 `check --wait` = **60.4초 완주** / `ask` 를 30초 안에 답함 = **6.4초 정상 성공**.

### 대신 이렇게 한다 — 2단계 조립 (실측으로 검증된 경로)

**1단계. 질문을 «보낸다»** — 막히지 않는다. 돌아온 `result.message.id` 를 ⛔**반드시 보관**한다.

~~~
orca orchestration send --to <coordinator handle> --from <자기 handle> \
  --type decision_gate --subject "<한 줄 질문 제목>" \
  --body "<질문 본문 · 고를 선택지가 있으면 함께>" \
  --task-id <taskId> --dispatch-id <dispatchId> --json
~~~

**2단계. 답을 «기다린다»** — 이 경로는 keepalive 가 켜지므로 **30초를 넘겨도 산다.**

~~~
orca orchestration check --terminal <자기 handle> --wait --types status --timeout-ms 600000 --json
~~~

* 답은 **`type:"status"`** 로 오고 **`thread_id` 가 1단계 메시지 id 와 같다.** ⛔**그 두 가지로 «내 질문의 답»인지 확인**한 뒤에만 따른다.
* `count:0` 으로 돌아오면 **실패가 아니라 «아직»** 이다 — **2단계만 다시 건다.** ⛔**1단계를 다시 보내지 마라** — 같은 질문이 원장에 중복 적재된다.
* **실측 근거** — 이 조립은 **35초 뒤에 온 답을 37.1초에 정상 수신**했다(`thread_id` 일치 확인).

### ⛔곁가지 — 「질문은 남고 묻는 사람만 사라진다」

`ask` 가 30초에 끊겨도 **질문 메시지는 원장에 그대로 남는다**(`read:0` · `delivered_at:null` — 실측). 즉 **답을 넣을 자리는 있는데 받을 사람이 없다.**
그리고 그 뒤에 도착한 답은 ⛔**조용히 버려진다** — 받을 소켓이 죽었으면 런타임이 쓰지 않고 끝내며, **오류도 나지 않는다.**
⇒ **`ask` 를 썼다가 끊겼다면 그 질문을 «없던 것»으로 치지 마라.** 답은 오지 않는다. §3-b 대로 escalation + 파일 표지를 남기고 정지한다.

### 이 절과 §3-b 의 관계 (정지 신고는 한 곳으로 모은다)

§3-b(막히면 알려라)는 **정지 신고**이고, 이 절은 **묻고 답받기**다. **질문에도 §3-b 는 그대로 적용된다.**
2단계 재대기를 **3회** 돌려도 답이 없으면 그때는 «막힘»으로 보고, §3-b 의 두 경로(escalation + 결과 파일 표지)를 ⛔**둘 다** 밟고 정지한다. **질문 실패는 별도 신고 형식을 만들지 않는다 — §3-b 하나로 떨어진다.**

⚠️ **정직 한계**: 이건 **회피지 벤더 수리가 아니다.** Orca 가 `isLongPollRequest` 에 `ask` 를 넣으면 이 절은 불필요해진다.
⛔**Orca 는 하루 1회 갱신되므로 갱신 뒤에는 30초 절단이 아직 유효한지 재확인한다** — 확인법 = 답 없이 `ask --timeout-ms 60000` 을 걸고 **30초 근처에 죽는지** 본다(죽으면 이 절 유지, 60초를 완주하면 벤더가 고친 것이다).
또한 이 파일은 **claude 좌석에만** 시스템 프롬프트로 실린다 — **codex 좌석에는 태스크 파일을 통해서만 도달**하므로 ORCH 가 태스크 파일에도 함께 적는다.
