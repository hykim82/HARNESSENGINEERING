## 2. 대조 규칙(코드로 내린 선택)

PM 설계 §(c)는 여러 지점을 [추론]으로 열어 두었다. 이 라운드가 고른
구체값:

- **대조 키 1순위** = 보내는함/받는함 본문의 `전달 #<번호>` 토큰과
  전달 파일 머리줄 번호의 완전 일치.
- **대조 키 2순위**(번호가 없는 출처) = 시각 창(±15분, 전달 머리줄
  분 자리가 `x`면 ±10분) **또는** 인용 앞 8글자(코드포인트 단위) 일치.
  둘 중 하나만 맞아도 매칭으로 친다 — 근거-부록 C의 실측("시각 창까지
  쓰면 대응 없음이 9건에서 1건으로 줄어든다")을 따른 것이다.
- **같은 분 다중 인용** = S1·S2를 합친 뒤 분(floor) 단위로 먼저 본
  것만 남긴다.
- **ㄱ-7 기록 누락**(오탐 방지 ⓑ) = 대응 없는 보내는함 항목이라도
  파일 이름이 `판정-<HHMM>`이고 받는함에 같은 HHMM의 `상신` 파일이
  있으면 ㄴ 후보가 아니라 별도 칸으로 센다.
- **형식 이전 구간** = 전달 파일에서 실제로 관측된 가장 오래된 유효
  머리줄 시각보다 앞선 출처 항목은 "형식 이전 · 미계수"로 따로 센다
  (소급 0 — PM 설계 §(b) "소급은 하지 않는다").
- **형식 오류** = 중복 번호(처음 것만 유효, 그 뒤는 전부 형식 오류) +
  `[책임자 경유 · ` 로 시작했지만 전체 정규식에 안 맞는 줄.

## 3. 한계(⛔줄이지 마라)

- 새 출처(전달 파일·보내는함·받는함)는 전부 같은 계정이 쓸 수 있는
  파일이다 = 보조 관측. 1-C 판정 자격 "없음"은 무변이다.
- 머리줄을 쓰는 규율(책임자가 매 항목 1줄을 더 쓰는 것) 자체는 CI
  밖이다 — 이 라운드가 지키는 것은 "안 쓰면 형식 오류 E · ㄴ 후보 K가
  값으로 보인다"는 것뿐이다.
- S3(책임자 세션 jsonl)·채팅 밖 채널은 미탐이고 크기를 알 수 없다
  (PM 설계 §(c) "미탐 방향").
- 라이브 실물 결과는 이 라운드가 병합되고, 책임자가 예약 감시
  (`OrchStallWatch`)에 `--relay-glob`/`--inbox-dir` 인자를 추가하고,
  전달 파일에 머리줄 형식이 실제로 시작된 뒤의 첫 회차에서만 값으로
  나온다.
